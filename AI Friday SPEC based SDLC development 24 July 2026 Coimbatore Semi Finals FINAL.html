Evaluation Criteria

The evaluation process will focus on the quality of each deliverable outlined in this document. Assessment goes beyond merely ensuring the software functions as intended. The effectiveness of AI tools and agents, as integrated across every phase of the Software Development Life Cycle, will be a primary consideration.

Every deliverable should be comprehensive, presented in a professional manner, and show clear completion. It is recommended to use AI tools to review all deliverables before finalizing them.

Maintain a comprehensive record of all prompts utilized for the creation of various deliverables. Ensure that you are logged into your tool during use so prompt history remains readily accessible.

Key Areas of Assessment

  • Comprehensive Application of AI: The use of AI in analysis, design, development, testing, and documentation must be demonstrated for all required outcomes.
  • Impactful Implementation: Evaluators will look for clear evidence of how AI technologies have positively influenced each stage of the software development process.
  • Deliverable Quality and Completeness: Each deliverable must be thoroughly developed, meeting all specified requirements with high quality and completeness.
  • Innovative Approach: Out-of-the-box thinking will be valued, especially in the creation of deliverables.

👥 Use case

AI Vendor Onboarding & Approval Assistant

Build an AI-powered application that simplifies vendor onboarding using a small, practical set of inputs: a vendor registration form, five to ten supporting documents, an onboarding checklist, a few compliance rules, and an approval matrix. The application should extract key information from the uploaded documents, create embeddings, store the relevant content in a vector database, retrieve applicable onboarding rules, identify missing or invalid documents, and guide the request through a simple approval workflow.

The solution should enable a requester or vendor to submit company details and documents, validate document completeness and expiry, retrieve relevant policy guidance through semantic search, generate an AI-assisted validation summary, request corrections when required, route risk or exception cases to a compliance reviewer, obtain procurement approval, notify the requester, and maintain a concise audit trail of the final decision.

Case Study

A procurement team needs to onboard a new service provider. The vendor submits a short registration form together with a registration certificate, tax document, bank proof, compliance declaration, and insurance certificate. The application extracts key fields, indexes the documents, compares the submission with the onboarding checklist, and retrieves the relevant compliance rules from a vector database. If a document is missing, expired, unreadable, or inconsistent, the system drafts a correction request and sends the case back for resubmission. When the document set is complete, the assistant prepares a risk and compliance summary. Standard cases move directly to procurement approval, while flagged cases are reviewed by compliance before the final decision. The approved vendor record, decision, supporting evidence, and status history are then retained for audit purposes.

Four-Hour MVP Scope

  • Small input set: one vendor form, five to ten text-searchable vendor documents, and three to eight reference documents containing the checklist, rules, and accepted-document guidance.
  • Core AI capability: text extraction, chunking, embeddings, vector search, checklist comparison, and an LLM-generated validation summary with cited source snippets.
  • Workflow roles: requester or vendor, procurement reviewer, and an optional compliance reviewer for risk or exception cases.
  • Demo paths: one happy path leading to approval, one missing-document path that loops back for resubmission, and one risk-flag path requiring compliance review.
  • Implementation boundary: OCR, external ERP integration, e-signature, and complex multi-country regulatory checks may be shown as future enhancements rather than built in the MVP.

📦 Deliverables

⚠ JURY EVALUATION REQUIREMENT: EVERY DELIVERABLE MUST INCLUDE MARKDOWN LANGUAGE INSTRUCTIONS USED FOR GENERATION OF FINAL DELIVERABLES. THESE MARKDOWN INSTRUCTIONS MUST BE SHOWN TO THE JURIES DURING EVALUATION.

All the deliverables are expected to be of production-level quality, ensuring excellence in both content and look & feel. The total score across the 10 deliverables is 100 marks. Each deliverable carries a different weight based on complexity, depth of thinking, implementation effort, and traceability value.

  1. Functional Requirements Document / User Stories – Cover functional and nonfunctional requirements, personas, user journeys, business rules, screen-level requirements, acceptance criteria, assumptions, constraints, and downstream development inputs.
  2. Application Architecture and Technical Architecture Diagrams – Provide logical, technical, integration, data flow, security, and AI-assist architecture views that explain how the solution works end to end.
  3. Database Design / Data Models – Use any RDBMS. Deliver logical model, physical model, ER diagram, key tables, relationships, constraints, sample records, and data dictionary. Do not use JSON as the primary data store.
  4. Story-to-Spec Decomposition (SSD) – Decompose the requirements into logical modules, epics, user stories, workflows, business rules, validation rules, and implementation-ready specification units.
  5. Wireframes / User Interface Design – Create clear wireframes or screen designs for reference-rule setup, vendor submission, document checklist validation, clarification requests, reviewer approval, status tracking, and audit history.
  6. SPECS / DSL in Markdown or YAML – Create structured Markdown or YAML specifications for each story component, including field definitions, screen behavior, validation rules, APIs or functions, and a hierarchical file tree layout.
  7. Software Code and Working Software – Build a working application that demonstrates reference-rule indexing, vendor package upload, mandatory-document validation, vector-based rule retrieval, LLM-assisted cited summary, clarification/resubmission workflow, approval or rejection, notification, and audit logging.
  8. Functional Test Scripts in CSV or Excel – Provide positive, negative, boundary, validation, workflow, exception, security, and AI-assisted output review test cases in a structured CSV or Excel format.
  9. Traceability Matrix in CSV or Excel – Map requirements, stories, specs, database fields, code modules, test cases, prompts, AI-generated outputs, and demo evidence to ensure end-to-end traceability.
  10. Code Quality Review Agent – Develop an AI-assisted review agent using Streamlit or another front end to evaluate the application code that has been developed as part of the exercise. The agent should review the code against a defined quality checklist and, where feasible, align the review output with common static code analysis practices such as SonarQube-style quality gates. The agent should assess maintainability, readability, modularity, coding standards, naming conventions, duplication, exception handling, security considerations, configuration handling, database access quality, test readiness, and traceability to the specifications. The output should include a quality score, checklist-wise findings, severity-wise observations, improvement recommendations, and an overall quality perspective for final submission readiness.

✅ Instructions

  1. Use AI tools or Build Your Own AI Agents (BYOAA) to develop the software and deliverables.
  2. Selection of Tools: Carefully evaluate and select the most suitable AI tools or frameworks for each phase of the project. If building custom AI agents, ensure they are scalable and maintainable. Additional weightage will be given if team builds their own AI agent to create the deliverables.
  3. Quality Standards: Adhere strictly to coding standards and best practices for software development. Apply consistent design patterns, code reviews, and automated testing to maintain high quality.
  4. Integration: Ensure seamless integration of components with the overall application architecture.
  5. Testing: Prepare comprehensive test cases, including both functional and non-functional scenarios.
  6. Documentation: Maintain clear and detailed documentation for all deliverables, including architecture diagrams, data models, and user manuals. Update documents regularly as changes are made.
  7. User Experience: Prioritise a user-centric approach in UI/UX design. Avoid using Streamlit or Gradio for the user interface.
